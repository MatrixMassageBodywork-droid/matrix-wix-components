# Page checkpoint template

Write a concise dated receipt using America/Chicago for the owner and an unambiguous timestamp for tooling.

- Status: DESIGNED / SAVED / VERIFIED / TESTED / PUBLISHED / NOT TESTED / BLOCKED, as applicable.
- Page/service, site/page ID, permanent URL, repository path, source commit/hash.
- Request scope and exact approved proof/revision; approval already given or still needed.
- Changes made; preserved boundaries; existing baseline links.
- Native custom-element ID/tag/source, actual section IDs and stretch/margins; measured desktop/mobile dimensions and method.
- Exact installed page-code file and readback result. Candidate code must remain clearly distinguished.
- SEO before/after: title, description, canonical, indexing/robots, schema IDs/count, visible H1 and full SEO body; intentional approved differences.
- Images: provenance, distinct service intent, uploaded mapping, lazy-load/crop check.
- Desktop/mobile, FAQ expansion, reviews/footer flow, link and image tests. Explicitly identify untested production mobile UA or other limitations.
- Save/readback and native Publish evidence. Publication count and timestamp, live revision verification. No publication claim if only a draft/proof exists.
- GitHub verified commit URL and canonical Drive receipt/evidence URL.
- Remaining action, if any, with exact dependency; do not rerun completed work.

Update the current README/manifest status and link the new receipt. Preserve historical documents without rewriting old approvals. A later verified receipt supersedes older pending-state documents for the same scope.
